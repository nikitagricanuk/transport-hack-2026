# Защита: редактор УДС — Транспортный хак 2026

Шпаргалка к выступлению: что показать, зачем это нужно и что отвечать. Цифры взяты из README и тестов,
перед защитой перепроверьте их на финальном файле.

## 1. Задача и гипотеза (1 мин)

- OSM — сырая карта: разорванные перекрёстки, тупики на краю выгрузки, неверные `oneway`, полосы без `turn:lanes`.
- MatSim, SUMO и Webots читают один и тот же `.osm`, поэтому одна ошибка графа ломает все три видео.
- Гипотеза: если правки графа делаются в несколько кликов и проверяются **до** отправки, исправленный файл
  проходит все три уровня, а инфраструктура ближе к реальной.

## 2. Ключевые функции и их ценность

| # | Функция | Ценность одной строкой |
| --- | --- | --- |
| 1 | Импорт/экспорт `.osm` без потерь (порядок, атрибуты, `<bounds>`, `<meta>`) | Сдаётся тот же файл, что пришёл, только с нужными правками: адаптеры не спотыкаются о шум сериализации |
| 2 | Правка узлов, рёбер, направлений, полос, мостов (`layer`), доступа по видам транспорта | Покрыт весь обязательный список ТЗ, а не только узлы и рёбра |
| 3 | Валидатор с учётом края выгрузки и автоисправления | Ошибки видны до сервера: 13 критичных → 0 на учебном участке, без ложных тупиков на `<bounds>` |
| 4 | Undo/redo для любой операции, горячие клавиши, шаблоны дорог | Правка в несколько клавиш вместо ручного редактирования XML |
| 5 | Локальная SUMO-проверка (`netconvert` в образе) | Ответ за секунды вместо очереди на сервере; ошибки SUMO ловятся до сдачи |
| 6 | Светофоры: постановка по правилам, фазы, оптимизация по Webster, экспорт `uds:signal:*` | Светофор ставится только на перекрёсток или переход; тайминг сохраняется в файле и не мешает адаптерам |
| 7 | Модель загрузки, перекрытия с объездом, OD-матрица | Видно последствия правки: закрыли Курчатова — поток ушёл на объезд (+138 с) |
| 8 | Маршруты ОТ и остановки | Автобусы входят в нагрузку, и видно, какие маршруты задевает правка |
| 9 | Режим «до/после», отчёты Excel/Word/PDF | Доказательная база для защиты и для заказчика |
| 10 | Совместная работа в реальном времени, автосохранение черновика | Команда правит один участок, а перезагрузка страницы ничего не теряет |
| 11 | Docker-образ и CI/CD | `docker compose up`: без ручной сборки, с теми же версиями, что на prod |

## 3. Демо-сценарий (5–6 мин)

1. **Открыть** `example.osm` со стартового экрана; показать карту на подложке.
2. **Проверка** → 4 критичных проблемы. Показать одну: разорванный перекрёсток или концы разделённой дороги
   на краю выгрузки.
3. **Исправить** кнопкой автоисправления, затем показать undo/redo.
4. **Ручная правка**: число полос и `oneway` на одной улице, светофор на перекрёстке Лермонтова × Жуковского,
   в панели светофора применить Webster.
5. **SUMO-проверка** → 0 ошибок, 3 светофора.
6. **Аналитика**: перекрыть ул. Академика Курчатова (way 80347185) и показать объезд и перераспределение
   потока на карте нагрузки.
7. **Экспорт** `<команда>.osm`; открыть `irkutsk_fragment_fixed.osm`; таблица «до/после» (0/0/17, одна компонента).
8. **Три видео** с сервера организаторов: исходник против исправленного файла.

Запасной план, если сервер или сеть недоступны: заранее записанные видео и локальная SUMO-проверка в контейнере.

## 4. Границы и честные ограничения

- Список «реальных» светофоров не сверялся с натурой; в выгрузке размечен только перекрёсток Лермонтова × Жуковского (2 светофора и 3 регулируемых перехода).
  Остальные добавляются инструментом после сверки с панорамами или снимками.
- `turn:lanes` редактор не выдумывает: без натурных данных стрелки по полосам не ставятся.
- Тайминг светофоров SUMO не читает (`uds:signal:*` — наши теги); фазы SUMO строит сам. Перенос в `.tll.xml`
  возможен, но требует id TLS из сети SUMO.
- Модель загрузки учебная (гравитационная модель, BPR), а не калиброванный спрос; спрос на сервере фиксирован
  организаторами.
- Объезд при перекрытии ищется только внутри выгрузки, поэтому на узком коридоре (ул. Добролюбова) его нет.

## 5. Вопросы и ответы

**Почему не JOSM?** JOSM — универсальный редактор: он не знает о трёх адаптерах, не проверяет готовность
к SUMO и не учитывает край выгрузки. У нас проверки и автоисправления заточены под этот конвейер.

**Не ломают ли ваши теги адаптеры?** Нет. `uds:fringe` и `uds:signal:*` — свои пространства имён, а адаптеры
неизвестные теги игнорируют. Файл с ними проходит `netconvert` без ошибок, и это покрыто тестом.

**Как вы доказываете, что граф стал лучше?** Счётчики валидатора (13/9/18 → 0/0/17), одна компонента связности,
`netconvert` без ошибок, встроенные задачи 3/3 и три видео с сервера.

**Что будет с новыми объектами при экспорте?** Они получают отрицательные id, а при экспорте перенумеровываются
в свободные положительные; существующие id не меняются.

**Работает ли на другом городе?** Да. Редактор работает с любым `.osm`; правила проверок завязаны на теги OSM,
а не на Иркутск.

**Сколько тестов?** 104 pytest-теста на бэкенд, плюс `ruff`, `npm run lint` и сборка образа в CI.
