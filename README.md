# Редактор УДС — Транспортный хак 2026

Визуальный редактор улично-дорожной сети: загрузить `.osm`, исправить граф (узлы, рёбра, направления,
полосы и манёвры, перекрёстки, мосты, светофоры, переходы) и сохранить **один `.osm`**, который без ручной
доработки проходит MatSim → SUMO → Webots на сервере организаторов.

## Быстрый старт (Docker)

Одна команда из корня репозитория — Compose сам соберёт образ, если его ещё нет:

```bash
docker compose up
```

Откройте http://127.0.0.1:8000. Стартовый экран показывает образцы из `/app/samples` (`UDS_SAMPLES_DIR`). `example.osm` — исходный фрагмент задания, `irkutsk_city.osm` — отдельная городская выгрузка для замеров.
Чтобы пересобрать образ после изменений в коде: `docker compose up --build`.

Образ по умолчанию **с SUMO** (`WITH_SUMO=1`, `eclipse-sumo==1.21.0`, около +320 MB): кнопка «SUMO-проверка»
запускает `netconvert` прямо в контейнере, а сборка проверяет `netconvert --version`. Так собирают и CI, и prod.
Облегчённый образ без SUMO:

```bash
WITH_SUMO=0 docker compose up --build
```

Контейнер слушает только localhost, процесс работает от пользователя `app` (uid 10001), healthcheck — `GET /api/health`.

## Разработка

### Linux

Бэкенд (Python 3.11+):

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload --port 8000
```

Проверки, из активированного окружения:

```bash
cd backend
pytest -q
```

Фронтенд (Node 20+), в другом терминале:

```bash
cd frontend
npm ci
npm run dev        # http://localhost:5173, /api проксируется на :8000
```

Сборка фронтенда: `npm run build` в `frontend/`.

### Windows

```bash
cd backend
python -m venv .venv
.venv\Scripts\pip install -r requirements-dev.txt
.venv\Scripts\python -m uvicorn app.main:app --reload --port 8000
.venv\Scripts\python -m pytest -q
```

Фронтенд так же: `npm ci` и `npm run dev` в `frontend/`.

Для кнопки «SUMO-проверка» установите в venv `pip install eclipse-sumo==1.21.0` — тогда экспортированный файл
прогоняется через `netconvert` локально, без ожидания сервера. Пути с кириллицей (например, профиль
`C:\Users\Пользователь`) netconvert не открывает, поэтому `sumo_check.py` пишет временные файлы в
`%PUBLIC%\uds-tmp` и запускает `netconvert` без кириллического `SUMO_HOME`.

## CI и деплой

Workflow [`.github/workflows/ci.yml`](.github/workflows/ci.yml) на push и pull request:

- бэкенд: `ruff check` и `pytest` (кэш pip);
- фронтенд: `npm ci`, `npm run lint`, `npm run build` (кэш npm);
- сборка Docker-образа (кэш слоёв GitHub Actions).

Push в `main` публикует образ с SUMO (`WITH_SUMO=1`) в GHCR:

- `ghcr.io/nikitagricanuk/transport-hack-2026:latest`
- `ghcr.io/nikitagricanuk/transport-hack-2026:<полный sha коммита>`

Для публикации workflow использует `GITHUB_TOKEN` с правом `packages: write`. Отдельный секрет для push не нужен.

Job `deploy` запускается только после успешной сборки, и только если событие — push в `main` или `workflow_dispatch` ветки `main`. На pull request job пропускается. `workflow_dispatch` заново образ не публикует: на сервер уезжает уже запушенный `:latest`.

На сервере (`deploy/remote-deploy.sh`):

1. Каталог `/opt/transport-hack`. Если его нельзя создать или в него нельзя писать — `~/transport-hack` пользователя `deploy`.
2. В каталог записывается [`deploy/docker-compose.prod.yml`](deploy/docker-compose.prod.yml): образ GHCR, порт только `127.0.0.1:8095`, `restart: unless-stopped`, healthcheck, логи `json-file` (max-size 10m, max-file 3), именованный том `transport-hack-data` на `/data`. Имя контейнера — `transport-hack-editor`.
3. `docker login ghcr.io` пишет токен только во временный `DOCKER_CONFIG` (`mktemp -d`, режим 700). Пароль — секрет `GHCR_TOKEN`, если он задан, иначе `GITHUB_TOKEN` этого job. `docker compose pull` использует этот каталог. Ловушка `EXIT` на любом выходе, в том числе после ошибки `pull`, `up` или `prune`, делает `docker logout` и удаляет каталог. В `~/.docker/config.json` токен не попадает.
4. `docker compose up -d --pull never` поднимает уже скачанный образ и в реестр больше не ходит, затем `docker image prune -f`.
5. `curl` `http://127.0.0.1:8095/api/health` до 15 раз с паузой 3 секунды. В ответе должно быть `"ok": true`, иначе job падает.

### Файл `app.env` на сервере

Кнопка «На сервер проверки» читает `ORGANIZER_TOKEN` и `TEAM_NAME` из окружения контейнера. На сервере они лежат в `app.env` рядом с `docker-compose.yml`: сейчас это `~/transport-hack/app.env` (если деплой идёт в `/opt/transport-hack`, файл там же). Скрипт деплоя перезаписывает только `docker-compose.yml` и `app.env` не удаляет и не затирает. Токен не попадает в git, образ, логи CI и секреты GitHub.

Создайте файл от пользователя `deploy`, режим `600`:

```bash
umask 077
cat > ~/transport-hack/app.env << 'EOF'
ORGANIZER_TOKEN=токен-команды
TEAM_NAME=hack-team7
EOF
chmod 600 ~/transport-hack/app.env
```

| Ключ | Назначение |
| --- | --- |
| `ORGANIZER_TOKEN` | токен команды, заголовок `Authorization: Bearer` на сервере проверки |
| `TEAM_NAME` | имя сдаваемого файла без `.osm`. Пример: `hack-team7` |

В compose файл подключён как `env_file` с `required: false`: если его ещё нет, контейнер всё равно стартует, а кнопка ответит, что переменные не заданы. После правки `app.env` в каталоге деплоя выполните `docker compose up -d`, чтобы контейнер перечитал окружение.

Nginx на сервере уже терминирует HTTPS для https://thack.nikitagricanuk.ru и проксирует на `127.0.0.1:8095`.

Сервер — RHEL 10, SELinux enforcing, Docker 29 и Compose v5. Пользователь SSH должен запускать `docker` без пароля (группа `docker`). В production нет bind-mount, поэтому `:Z` не нужен. Если позже примонтируете каталог с хоста, добавьте суффикс `:Z`. Чужие контейнеры не используются: свой проект `transport-hack`, свой контейнер, порт и том.

### Приватный или публичный пакет GHCR

Пакет **может оставаться приватным**. Deploy логинится в `ghcr.io` перед `docker compose pull`, так что открывать пакет не обязательно. Первый push из `main` создаёт приватный `ghcr.io/nikitagricanuk/transport-hack-2026`.

Публичным (Package settings → Change visibility → Public) его стоит делать только если нужен `docker pull` без токена. Этому workflow это не требуется. Если pull с `GITHUB_TOKEN` вернёт 403, задайте `GHCR_TOKEN` (PAT с `read:packages`) либо откройте пакет.

## Проверка и исправление фрагмента Иркутска

Редактор **находит ошибки и предлагает исправления; применяет их пользователь**. При открытии файла ничего
не меняется, пакетного «исправить всё» нет. У каждой проблемы 1–3 варианта (например, «Присоединить» или
«Удалить фрагмент»). По клику вариант сначала показывается на карте: зелёным — что добавится, красным
пунктиром — что удалится, синим — что изменится (`POST /api/documents/{id}/fix-preview`, документ при этом
не меняется). Если вариант удаляет дорогу, карточка показывает её длину и не даёт применить его, пока
пользователь не подтвердит, что дороги нет в реальности. Применённая правка попадает в историю
(отмена — Ctrl+Z) и в журнал правок с автором и временем.

Валидатор учитывает край выгрузки: дорога, уходящая за `<bounds>`, считается связанной с внешней сетью, а не
тупиком. Поэтому на сыром `example.osm` критичных ошибок стало меньше: правок для этого не понадобилось,
просто ушли ложные срабатывания.

| `example.osm` (без правок) | Критично | Предупреждения | Инфо | Компонент связности |
| --- | --- | --- | --- | --- |
| прежний валидатор | 13 | 9 | 18 | — |
| текущий валидатор | 4 | 4 | 21 | 4 |

Исправленный файл получается вручную, в редакторе: каждая правка выбрана и проверена человеком, а список
правок с причинами ведётся в `docs/fix-log.md`. Локальный `netconvert` 1.21.0 на сыром `example.osm`:
0 ошибок, 3 светофора (`tlLogic`).

Демо перекрытия: ул. Академика Курчатова (way 80347185). Объезд находится по 11 рёбрам, +138 с,
и весь поток перераспределяется. У ул. Добролюбова объезда нет, потому что выгрузка — узкий коридор.

## Проверки по нормам

Как и остальные, эти проверки только предлагают исправление: пользователь смотрит превью и применяет его сам.

| Проверка | Почему важно | Норма | Исправление |
| --- | --- | --- | --- |
| Нет `maxspeed` у магистральной или районной дороги (предупреждение), у жилой улицы (замечание) | Без знака каждый симулятор берёт своё значение по классу: ул. Лермонтова (secondary) получает 100 км/ч в SUMO с typemap по умолчанию и 30 км/ч в MatSim | ПДД РФ, п. 10.2: 60 км/ч в населённом пункте, 20 км/ч в жилой зоне | `maxspeed=60` (или 20) |
| `maxspeed=RU:urban` / `RU:living_street` | SUMO читает сокращение как 60 / 20, MatSim понимает только число | ПДД РФ, п. 10.2 | заменить на число |
| Запрет поворота не применится | В выгрузке запрет ссылается на рёбра вне фрагмента, или узел `via` не на концах `from`/`to`; netconvert такой запрет пропускает | — | «Удалить отношение» или «Исправить via» |
| Резкий перепад высоты | Webots строит полотно по `ele`; ступенька у моста — провал машин | СП 42.13330.2016, разд. 11: 50 ‰ (motorway/trunk), 60 ‰ (primary), 70 ‰ (secondary), 80 ‰ (прочие) | «Плавный Z» |

«Плавный Z» поднимает мост или опускает тоннель на `layer × 5 м`. Съезд строится по расстоянию по дорожной сети от концов моста, длиной «высота / допустимый уклон», например 5 м при 70 ‰ дают около 75 м. Если съезд заходит на дорогу более строгого класса, длина пересчитывается. Соответствие классов OSM категориям улиц СП принято нами. Не проверено, снижает ли климатический подрайон Иркутска эти значения: мы берём табличные значения как есть.

Проверено на сыром `example.osm`:
- Без правок проверка отмечает 8 магистральных и районных рёбер без `maxspeed`, 6 рёбер с `RU:urban` и 7 запретов поворота со ссылками за выгрузку.
- После применения предложенных исправлений netconvert даёт 60 км/ч на всех рёбрах ул. Лермонтова (было 100) и 0 сообщений «Ignoring restriction» (было 9).
- После «Плавного Z» на всех 11 мостах и тоннелях остаётся одно предупреждение об уклоне: там, где подъём на мост (+5 м) и спуск в тоннель (−5 м) слишком близко друг к другу по дороге, чтобы уложиться в норму. Это противоречие в самих данных, и проверка его честно показывает.

## Светофоры

Светофор — узел `highway=traffic_signals` на перекрёстке. Регулируемый переход — `highway=crossing` +
`crossing=traffic_signals`; инструмент сам выбирает тег по месту. По этим узлам SUMO ставит TLS
(`netconvert --tls.guess-signals`), а фазы строит сам.

Тайминг из панели светофора (цикл, доля зелёного главного направления, Webster) попадает в экспорт
тегами `uds:signal:*` на узле светофора. Адаптеры неизвестные теги игнорируют, поэтому файл остаётся
валидным. Повторный импорт восстанавливает план, а сброс тайминга убирает теги.

| Тег | Пример | Значение |
| --- | --- | --- |
| `uds:signal:cycle` | `100` | длительность цикла, с (30–180) |
| `uds:signal:main_share` | `0.60` | доля зелёного главного направления (0.2–0.8) |
| `uds:signal:green_main` | `54` | зелёный главного направления, с |
| `uds:signal:green_cross` | `36` | зелёный пересекающего направления, с |
| `uds:signal:yellow` | `3` | жёлтый, с |

Зелёный = (цикл − 10 с потерь) × доля. Файл с такими тегами проходит `netconvert` без ошибок, TLS на месте.

## Воспроизводимость на городской сети

Из корня репозитория можно получить дорожную сеть в границах прямоугольника Иркутска и измерить операции через API. Для замера SUMO в окружении нужен `netconvert`.

```bash
python backend/scripts/fetch_city.py --tiles 2
python backend/scripts/bench.py data/irkutsk_city.osm
```

Городской образец `irkutsk_city.osm` содержит 86 200 узлов и 17 622 линии дорог. Источник — [OpenStreetMap](https://www.openstreetmap.org/copyright), лицензия ODbL. Прямоугольник выгрузки — 52,20–52,36° с. ш., 104,15–104,40° в. д.

Загрузите полученный `.osm` через стартовый экран редактора. Загрузчик объединяет четыре ответа Overpass и проверяет, что у каждого ребра есть все узлы. Бенчмарк измеряет открытие, валидацию, превью, SUMO и экспорт. Граф во время замера сохраняет исходные теги и геометрию.

Замеры на образце 21,3 МБ. На Windows (Intel Core i5-12450H) использован `bench.py` с вызовами API внутри процесса. Для Linux измерены полные HTTP-запросы к серверу `thack.nikitagricanuk.ru` 10 ноября 2026 года. Время серверного столбца включает передачу ответа по сети.

| Операция | Windows, `bench.py` | Linux, сервер по HTTPS |
| --- | ---: | ---: |
| Открытие и подготовка слоя карты | 3,02 с | 145,11 с |
| Валидация | 47,23 с | 79,41 с |
| Превью одной правки | 0,19 с | 3,24 с |
| Проверка SUMO (`netconvert`) | — | 24,10 с |
| Экспорт | 0,69 с | 137,07 с |

В обоих замерах валидатор сообщил 77 критических проблем, 1 013 предупреждений, 3 264 замечания и 73 компоненты связности. Проверка SUMO на сервере завершилась с 0 ошибок и 67 предупреждениями. Серверный прогон использовал исходный городской образец и одно превью.


## Как устроено

```
frontend (React + MapLibre)  ──HTTP──▶  backend (FastAPI)
  карта, инструменты, панели             OsmDocument (модель без потерь)
                                         History (снимки до/после → undo/redo)
                                         validate()  → проблемы + fix-операции
                                         to_xml()    → team.osm
```

Каждая правка — POST `/api/documents/{id}/ops` c `{op, args}`; ответ содержит новое состояние карты.
Новые объекты получают отрицательные id и при экспорте перенумеровываются в свободные положительные.

| POST | `/api/documents/{id}/batch` | несколько операций одним шагом отмены |
| POST | `/api/documents/{id}/undo`, `/redo` | отмена / повтор |
| GET | `/api/documents/{id}/validate` | проверка графа |
| POST | `/api/documents/{id}/fix-preview` | превью исправления `{op, args}`: что добавится, удалится, изменится; документ не меняется |
| GET | `/api/documents/{id}/edit-log` | журнал применённых правок (Markdown) — основа для `docs/fix-log.md` |
| GET | `/api/documents/{id}/export?filename=team1` | скачать `.osm` |
| POST | `/api/documents/{id}/check/sumo` | прогон `netconvert` |
| POST | `/api/documents/{id}/check/organizer` | отправить экспорт на сервер проверки |
| GET / DELETE | `/api/draft` | восстановить или сбросить автосохранение |

Обновление страницы не теряет правки: id документа лежит в `localStorage`, а сам файл — в `data/drafts/`. Если процесс сервера ещё жив, восстанавливается и история undo.

Отправка на сервер организаторов (`POST /api/submit`, заголовок `Authorization: Bearer`, multipart-поле `osm`, файл `{TEAM_NAME}.osm`) включается переменными окружения:

```bash
export ORGANIZER_TOKEN=...   # токен команды
export TEAM_NAME=...         # имя файла на сервере, без .osm
# необязательно, если сервер не на адресе по умолчанию:
# export ORGANIZER_URL=http://innerlogistics.lovethosetrains.com:7078
```

Кнопка «На сервер проверки» пишет понятную ошибку, если `ORGANIZER_TOKEN` или `TEAM_NAME` не заданы.
На сервере их задаёт `app.env` рядом с compose — см. раздел «Файл `app.env` на сервере».

Операции: `set_tags`, `set_lanes`, `move_node`, `add_node`, `insert_node`, `add_way`, `delete`,
`split_way`, `merge_nodes`, `connect_endpoint`, `reverse_way`.

## Сдача

Имя файла должно совпадать с названием команды — поле рядом с кнопкой «Экспорт .osm».
Загрузите файл на сервер проверки с токеном команды и дождитесь трёх видео.

## Анализ (задачи 1–4 прошлого хакатона)

В режиме «Аналитика» доступны четыре инструмента:

- **Маршрут**: две точки, узла или здания, авто/пешком, минимум времени или длины. Для авто учитываются запреты поворотов с via-узлом; неприменимые отношения перечислены. Разрыв сети и одностороннее препятствие дают карточку с проверяемым исправлением. Предпросмотр пересчитывает маршрут на временной копии правки и откатывает её.
- **Доступность ОП**: два набора остановок (выезд/возврат), ручной выбор А → Б → убрать или первые два направления маршрута. Предел в метрах (500 м по умолчанию) или минутах; зоны А, Б, пересечение и непокрытая часть района. Здания классифицируются по доступности их центроидов; население не вычисляется.
- **Изохроны**: авто/пешком, шаг 0,5/1/2/5 мин, до 10 зон и не более 60 мин. Площадь и километры сети, включая частичные сегменты; свободные скорости либо сценарий BPR, с опциональными перекрытиями.
- **Доступность на ОТ**: пешком + ожидание + поездка; отдельные результаты без пересадок и с 0–3 пересадками. Интервалы редактируются вручную для каждого отношения маршрута. **«Заполнить тестовыми данными»** подставляет синтетические интервалы 4–20 мин с явными метками в таблице и на карте. Ручной ввод заменяет метку тестового значения. «Сбросить интервалы» возвращает OSM interval, иначе подписанные 10 мин по умолчанию. Эти параметры живут в клиентском анализе и не записываются в OSM или сценарий нагрузки. По согласованному изменению задания импорт ИД7/xlsx заменён ручным вводом и тестовым заполнением; подтверждённого покрытия «24 из 38» в этой версии не заявляем.

Все `/api/documents/{id}/analysis/*` — **read-only**: без правок, ревизий, журнала и рассылок соавторам. Сравнение с исходным файлом использует загруженный OSM, а не сохранённый пользовательский сценарий. Исправление из карточки переключает в редактирование и требует «Применить» в обычном предпросмотре. Причина исправления сохраняется в отдельном поле истории и выводится в колонку «Почему» журнала.

Пешеходные проверки — отдельный фильтр **«Пешеходы»**, severity `info`, без влияния на MatSim/SUMO/Webots. Проверяются отсутствие тротуара, съезды/тоннели, параллельный отдельно нарисованный тротуар и отсутствие подхода к остановке в пределах 60 м. Результаты — предложения для проверки пользователем.

Ограничения: высот нет, поправка на рельеф не применяется; скорость пешком 4,5 км/ч и ОТ 20 км/ч, ожидание ½ интервала, коридоры 40/30 м — регулируемые/подписанные допущения. Ступени без отдельного штрафа. Concave hull 0,3 — отрисовка, не доказательство доступа к любой точке внутри полигона. Классы зданий определяются сетевым коридором вокруг достигнутых сегментов. Внешние части маршрутов за пределами фрагмента не соединяются фиктивными прямыми. У границы показывается предупреждение о занижении зоны. ИД5/ИД6/ИД8 отсутствуют; задачи 5–6 не реализованы.

Проверка производительности анализов включена в `backend/scripts/bench.py`: `python backend/scripts/bench.py data/example.osm --no-sumo`. Скрипт использует отдельный временный черновик, только анализирует и выполняет один откатываемый предпросмотр, без применения исправлений.

Замер 10.11.2026 в managed Linux workspace, `bench.py --no-sumo`, без применения правок (время HTTP-запроса, холодная сборка графа включена):

| Анализ | example.osm, 6 089 узлов | irkutsk_city.osm, 86 200 узлов |
| --- | ---: | ---: |
| Маршрут | 0,14 с | 7,17 с |
| 5 автомобильных изохрон | 0,82 с | 11,68 с |
| Два набора ОП | 0,60 с | 9,67 с |
| ОТ, 5/10/15 мин | 0,61 с | 4,24 с |

Это измерения конкретных стартовых точек скрипта, не гарантия для любого запроса и не серверный production-бенчмарк. Буфер строится по коротким достигнутым сегментам с последующим каскадным объединением полигонов; это исключает многоминутную буферизацию общего линейного графа города.
